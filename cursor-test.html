Stickman cursor test page

Scaffolding, not part of the site. It exists because index.html has no links, no buttons, no form fields, and is shorter than one viewport, so most of the cursor's behaviour cannot be observed on it at all. The checklist at the bottom of cursor-plan.md is meant to be run here.

Controls. Move the mouse and the stickman chases it. Press any of W, A, S, D to switch to keyboard mode. Enter activates whatever the stickman is standing on, Space jumps, and Escape turns the whole thing off and remembers that you did.

Type wasd into that field and then press Space. All five characters should appear, the stickman should neither move nor jump, and the page should not scroll away underneath you.

Now scroll

The test link is deliberately far below this point, so reaching it with the keyboard means using the edge auto-scroll rather than just walking across the screen. Hold S until the stickman reaches the bottom band of the window and the page should start scrolling, faster the closer it gets to the edge. Hold W at the top to come back.

While you are down there, check the one that makes this feature tolerable rather than infuriating: switch back to the mouse, park the pointer at the very bottom of the window, and confirm the page does not scroll. Edge auto-scroll is keyboard mode only.

Everything below is filler to give the page height. There is nothing to read here, which is rather the point: the interesting part is whether the scrollbar moves when it should and stays put when it should not.

Filler. A page that fits in one viewport has no scrollbar, and without a scrollbar neither the Space suppression nor the edge auto-scroll can be verified, because both of them are claims about scrolling that has been prevented or caused. A check that cannot fail is not a check.

Filler. The Space suppression is the one most likely to pass by accident. Watch the scrollbar itself rather than the text, because a page that happens to be scrolled to the bottom already cannot scroll any further and will look like a pass whatever the code does.

Filler. Mouse wheel, PageUp and PageDown should all still scroll normally. Only Space and the arrow keys were taken: Space because it is the browser's page-down key and jumping would otherwise page the document down on every press, the arrows because they now walk the stickman.

Filler. The stickman is position: fixed, so it stays put on screen while the content moves underneath it. Its hotspot is in viewport coordinates, which is why elementFromPoint keeps returning whatever is now underneath rather than whatever was there before the scroll.

Filler. The hotspot sits at the centre of the sprite's 64x64 cell, which is roughly the stickman's chest. In the punch frames the fist reaches about 15px further than that, so the figure visibly punches past what it actually activates. That is a known trade-off and not a bug: the centre is also what scaleX(-1) mirrors about, so the click point does not shift when the figure turns around.

Filler. Jumping applies a parabolic offset to the drawing only. The tracked position never moves, so a jump can never mis-aim a punch, and walking to just above the bottom band and jumping should not scroll the page even though the picture briefly rises into it.

Filler. Punch outranks jump, so pressing Enter in mid-air gives an air punch with the arc continuing underneath it. WASD stays live in the air too, so the stickman can drift while jumping.

Filler. Hovering the link, the button, and the text field should show no native cursor at all: no hand, no I-beam, no arrow. Browser default stylesheets set their own cursor on those three, which beats an inherited value, so this only works because cursor.css says html.stickman-active *.

Filler. Toggling Windows dark mode should leave the stickman clearly visible against both backgrounds, because it is drawn as a CSS mask filled with the inherited text colour rather than as a black image.

Filler. In the Network tab, five sheets should return 200: Thin.png, Run.png, Punch.png, Jump.png, and JumpDown.png. JumpUp.png should never be requested at all, because it is byte-identical to a cell of Jump.png. Any red 404 here is a path bug, which is the failure the P1 README warns about hardest.

Filler. Press Escape and the native arrow comes back, the sprite disappears, and any in-flight scroll stops. Reload and it should stay off, which is the only thing that proves the preference is read at startup rather than merely written.

Filler. Almost there.

The link target

A link, for the punch and focus checks. It is an in-page anchor on purpose: a link that navigated away would end the test session and lose all the state you just set up, while an anchor jump is just as observable and leaves you on the page.

Stand the stickman on that link and press Enter. The ten-frame punch should play once, not loop, and the page should jump to the anchor. Press Enter over empty space and the punch should still play, but nothing else should happen.

Then press Tab until the link is focused and press Enter again. This time the browser should follow it natively and the stickman should not punch at all, because Enter belongs to the focused control.
